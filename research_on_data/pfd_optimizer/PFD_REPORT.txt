--------------------------------------------------------------------------------
1. ЧТО ТАКОЕ PFD
--------------------------------------------------------------------------------

Price-Flow Divergence (PFD) - индикатор дивергенции цены и торгового потока.
Идея: сравнить, насколько сильно цена уже ушла за окно W с тем, какой
накопленный поток покупок/продаж был за это же окно. Если цена и поток
расходятся, это рассматривается как сигнал о продолжении или развороте
движения.

В текущей реализации используется формула:

    comb = pz - intz

где:
    pz   - нормированный моментум цены за окно W;
    intz - t-статистика среднего нормированного потока за окно W.

Сигнал:
    comb >= +sigma  -> Buy  (+1)
    comb <= -sigma  -> Sell (-1)
    иначе           -> нейтрально (0)

--------------------------------------------------------------------------------
2. КАК СЧИТАЕТСЯ ИНДИКАТОР
--------------------------------------------------------------------------------

2.1. Агрегация 1s-данных в интервалы interval_sec

Для каждого интервала:
    buyAcc  = sum(buy_vol)
    sellAcc = sum(sell_vol)
    flow    = (buyAcc - sellAcc) / (buyAcc + sellAcc), если сумма > 1e-12,
              иначе 0.0

Цена закрытия интервала:
    price_mid = vwap последней секунды интервала (price_source=vwap)
                или close последней секунды (price_source=close)

2.2. Скользящие буферы

    price_series - длина W + 1
    flow_series  - длина W + 1

Пока буферы не заполнены (меньше W+1 точек), сигнал не считается.

2.3. Моментум цены

    tr = price_series[-1] / price_series[0] - 1

В окне W+1 точек это доходность ровно за W интервалов.

2.4. Волатильность цены

    rets[i] = price_series[i] / price_series[i-1] - 1,  i = 1..W
    meanRet = mean(rets)
    sigPx   = sqrt( sum((rets[i] - meanRet)^2) / (W - 1) ) * sqrt(W)

Используется выборочное СКО (ddof=1), затем масштабирование на sqrt(W).

2.5. Статистика потока

    flow_window = flow_series[-W:]     # последние W значений, не W+1
    meanFlow    = mean(flow_window)
    stdFlow     = sqrt( sum((flow[i] - meanFlow)^2) / (W - 1) )

2.6. Нормировки и итоговый score

    pz   = tr / sigPx
    intz = meanFlow * sqrt(W) / stdFlow
    comb = pz - intz

Защита:
    если sigPx < 1e-9 или stdFlow < 1e-9 -> comb = 0, сигнал нейтральный.

2.7. Соответствие C++

Python-реализация проверена на синтетических данных против прямой наивной
реализации циклов из C++:
    trading_strategy/indicators/price_flow_divergence/price_flow_divergence.cpp
    trading_strategy/settings.h
Компоненты tr, pz, intz, sigPx, stdFlow и comb совпадают.

3. КАК ПРОВОДИЛСЯ ПОДБОР
--------------------------------------------------------------------------------

3.1. Walk-forward разбиение

Данные режутся по календарным дням:
    train = предыдущие K дней
    test  = следующие M дней

Режимы:
    expanding - train начинается с первого дня данных и растет;
    rolling   - train фиксированной длины K дней.

Если train_days/test_days не заданы, используется:
    block = total_days // (n_folds + 1)
    train_days = test_days = block

Для 36 дней и n_folds=5 это дало train_days=test_days=6.

Индикатор считается каузально по всей истории, а затем нарезается на
train/test. Это дает корректный прогрев тестового фолда без утечки будущего.

3.2. Основная сетка (по ТЗ)

    interval_sec:  [10, 20, 30, 60, 120, 180, 300]
    window_size W: [30, 60, 120, 180, 360, 720]
    sigma:         [1.0, 1.5, 2.0, 2.5, 3.0, 3.5]
    price_source:  [vwap, close]
    take_profit:   [0.005, 0.0075, 0.01]
    stop_loss:     [0.0025, 0.005, 0.01]
    max_hold_sec:  [1800, 3600, 7200, 14400]

Итого 18 144 конфигурации.

3.3. Дополнительные исследовательские параметры

Добавлены для проверки гипотез:
    signal_mode:          momentum / reversal
    confirm_intervals:    требовать N предыдущих сигналов того же знака
    trend_ema_span:       EMA-фильтр по цене, span в интервалах
    trend_filter_mode:    aligned / against
    direction:            both / long / short
    pz_weight:            вес pz
    intz_weight:          вес intz
    trend_strength_min:   минимальное |price/EMA - 1|
    autocorr_window:      окно rolling lag-1 автокорреляции доходностей
    autocorr_mode:        follow / fade
    autocorr_threshold:   порог автокорреляции
    vol_window:           окно rolling-медианы волатильности
    vol_ratio_min/max:    допустимый диапазон sigPx / rolling_median(sigPx)

3.4. Бэктест

    - одна позиция одновременно;
    - сигналы, пока позиция открыта, игнорируются;
    - вход по close секунды, в которую зафиксирован сигнал;
    - выход по первому из: TP, SL, timeout;
    - TP/SL проверяются по high/low каждой секунды удержания;
    - если в одной секунде задеты TP и SL, считается SL (conservative);
    - издержки применяются к обеим сторонам сделки;
    - PnL для short: -(exit/entry - 1);
    - сделки обрезаются границей фолда.

3.5. Критерий выбора на train

    objective: sharpe / profit_factor / net_pnl / calmar
    дополнительно: min_trades, min_win_rate

Метрики на test:
    net PnL %, число сделок, win rate, gross win rate, profit factor,
    Sharpe по сделкам (mean/std * sqrt(N), не annualized),
    max drawdown по equity закрытых сделок, средняя длительность,
    число Buy/Sell сигналов, доля времени в позиции, Calmar,
    expectancy, TP/SL/timeout breakdown.

3.6. Оптимизация вычислений

Исходная версия пересчитывала индикатор Python-циклами и для каждого
интервала заново сканировала секунды удержания. Это давало ~2 часа даже
на маленькой сетке.

Что сделано:
    - агрегация интервалов и rolling-статистика векторизованы;
    - компоненты PFD считаются один раз на (interval, W, price_source);
    - сигналы переиспользуются для всех TP/SL/hold;
    - бэктест ищет первое касание TP/SL через NumPy, без pandas-итераций.

Фактическое время:
    config_small.yaml (9.7 дней)                  ~1.4 сек (было ~2 часа)
    config.yaml, 18 144 конфига, 9.7 дней         ~4 мин
    config.yaml, 18 144 конфига, 36 дней          ~9 мин (127 008 бэктестов)
    regime-grid, 62 208 конфигов, 36 дней         ~8.7 мин (311 040 бэктестов)

4.2. Чистый pz (intz_weight = 0) для сравнения

На горизонте 4-6 часов pz показывает более высокую directional accuracy,
чем comb:

    interval=60s, W=360, горизонт 4 часа, хвост 2.5%:

    interval=60s, W=360, горизонт 6 часов, хвост 1%:
        accuracy = 69.1% (long 74.7%, short 63.4%)
        с фильтром по EMA120 long: ~74.7%, net после комиссий +0.30%

Но это режимно-зависимо. По хронологическим блокам точность падает:
    трендовые блоки: 88-99%
    середина выборки (range/reversal): 0-30%
Поэтому средняя ~69% не означает устойчивые 70%.

4.5. Итоговая интерпретация

    - Исходный comb = pz - intz на текущих данных имеет слабое и
      нестабильное преимущество. Без фильтров устойчивого плюса нет.
    - Фильтр волатильности (торговать только в нормальном режиме,
      0.8-1.2 от 12h медианы sigPx) дает небольшое улучшение:
      появляются конфигурации с 20+ сделками и положительным PnL.
    - Автокорреляция и сила тренда в протестированных вариантах
      не улучшили результат.
    - Чистый pz лучше работает на горизонте 4-6 часов, но требует
      другого управления выходом (time-exit / более широкий SL).
    - Устойчивых 70% на этом файле достичь не удалось. 70%+ появляются
      только на очень редких сигналах (7-11 сделок) или в отдельных
      трендовых блоках, что статистически незначимо.
    - Основные ограничения: 36 дней данных, мало независимых режимов,
      высокая комиссия 0.16% на сторону, TP/SL 0.5-1% срезают движение
      раньше, чем оно успевает реализоваться.

Вывод: выход по противоположному PFD не улучшает результат.

mean net/фолд ниже, чем без exit-фильтра. При T=0-2.0 результат
существенно хуже: противоположный сигнал часто срабатывает на
обычном откате внутри тренда и срезает прибыльные сделки.

Причина: у лучшего конфига асимметричная структура TP 2% / SL 0.5%.
Такая стратегия должна давать прибыли расти; раньше времени
выходить из нее контрпродуктивно. Для управления риском логичнее
тестировать не opposite PFD, а trailing-stop, break-even stop или
частичное закрытие прибыли.

4.9. Проверка Trailing-stop

Проверялся trailing-stop на лучшем конфиге из раздела 4.7:

    interval=60s, W=120, sigma=3.0, confirm=1, intz_weight=1.0,
    vol_ratio >= 0.8, TP=2%, initial SL=0.5%, max_hold=24ч.

Правило:
    - initial SL 0.5% остается до активации;
    - после прибыли >= activation стоп начинает тянуться за максимумом
      (для long) / минимумом (для short) на расстоянии distance;
    - стоп двигается только в сторону прибыли;
    - при одновременном касании TP и стопа в одной секунде стоп считается
      первым (conservative_intrabar=true).

Сетка: activation = 0, 0.25%, 0.5%, 1.0%, 1.5%, 2.0%;
       distance   = 0.25%, 0.5%, 0.75%, 1.0%, 1.5%.

Лучшие / характерные варианты (5 test-фолдов):

  Activation  Distance  Сделок  Win rate  Mean PnL  PF     Mean net/фолд  Median Sharpe  Median DD  Прибыльных
  нет         нет       22       54.5%     +0.383%   2.13   +1.684%        0.514          0.913%     80%
  1.5%        1.5%      22       54.5%     +0.384%   2.13   +1.689%        0.514          0.888%     80%
  0.25%       0.5%      28       60.7%     +0.240%   2.22   +1.344%        0.942          0.820%     80%
  0.5%        0.5%      27       59.3%     +0.223%   2.01   +1.205%        0.942          0.820%     60%
  0%          0.75%     26       53.8%     +0.260%   2.17   +1.350%        0.787          0.854%     80%
  0%          0.5%      28       57.1%     +0.152%   1.70   +0.850%        0.273          0.636%     80%
  0%          0.25%     50       16.0%     -0.201%   0.31   -2.011%       -1.540          2.061%     20%

Выводы:

  1. Trailing-stop не улучшает net PnL. Лучший по net вариант с trailing
     практически совпадает с baseline (1.5%/1.5%), потому что стоп
     срабатывает всего один раз.
  2. Tight trailing (0.25-0.5%) повышает win rate и Sharpe, немного снижает
     max DD, но заметно снижает net PnL: +1.34% против +1.68% на фолд.
     Причина - стоп выбивает прибыльные сделки на обычных откатах.
  3. Очень tight trailing (0.25%) разрушает стратегию: 50 сделок, win rate
     16%, PF 0.31.
  4. Если цель - максимальный net PnL, фиксированный TP 2% / SL 0.5%
     лучше. Если цель - более гладкая equity curve и выше Sharpe,
     trailing 0.5% после +0.25% может быть компромиссом, но ценой
     меньшей доходности.

Логичный следующий шаг: partial take-profit (например, 50% на +1%)
+ trailing-stop для остатка. Это может сохранить часть крупных движений,
но снизить риск отката.

Скрипт: research_trailing.py
(пишет output/research/trailing_test_summary.csv).


4.10. Адаптивный TP/SL в зависимости от волатильности

Гипотеза: в спокойном режиме ставить TP 1.5%, в волатильном TP 2.0%,
SL оставлять 0.5%. Проверялись два определения режима:
  - ATR ratio = ATR(window) / rolling_median(ATR, 720);
  - PFD vol_ratio = sigPx / rolling_median(sigPx, 720).

Основной вход без изменений:
    interval=60s, W=120, sigma=3.0, confirm=1, intz_weight=1.0,
    vol_ratio >= 0.8, SL=0.5%, max_hold=24h.

Лучшее простое правило:
    если vol_ratio < 1.0 -> TP 1.5%, иначе TP 2.0%; SL 0.5%.
