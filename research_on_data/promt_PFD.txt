Я занимаюсь написанием торговой стратегии для криптовалютной биржи Bybit
Цель - забирать 0.5 - 1.0% движения цены в рамках до одного дня.
В рамках этой стратегии нужно разработать индикаторы для предсказания будущего движения цены
с высокой вероятностью.

Твоя задача - yfgbcfnm Python-скрипт для офлайн-подбора гиперпараметров индикатора Price-Flow Divergence (PFD) на исторических данных Bybit.

1. Входные данные.
Входными данными является .csv файл, расположенный по пути:
research_on_data/aggregated_1s/aggregated_1s.csv

В нем хранятся данные за каждую 1 секунду:
ts, open, high, low, close, buy_vol, sell_vol, trade_count, vwap
где:
- ts — начало секунды, мс UTC (int64)
- цены — float
- buy_vol / sell_vol — объём в базовом активе, разбитый по направлению сделки
- trade_count — число сделок за секунду
- vwap — средневзвешенная цена по всем сделкам секунды

Данные в файле представлены за несколько дней работы.

2. Индикатор PFD - это классический индикатор, основанный на дивергенции
цены и объема.

У меня уже написана логика работы индикаторы - она представлена в файлах:
trading_strategy/indicators/price_flow_divergence/price_flow_divergence.cpp
trading_strategy/settings.h

Индикатор работает не на каждой секунде, а на интервалах interval_sec (по умолчанию 60 с),
предполагаемый диапазон подбора 10–300 с. На каждом интервале:

1) Накопление потока за интервал:
buyAcc = sum(buy_vol) за интервал
sellAcc = sum(sell_vol) за интервал
flow = (buyAcc - sellAcc) / (buyAcc + sellAcc), если buyAcc + sellAcc > 1e-12, иначе 0.0

2) Цена закрытия интервала: mid_price — использовать vwap последней секунды интервала (или close — параметризовать выбор).

3) Скользящие буферы price_series и flow_series длины W + 1, где W = window_size (по умолчанию 360),
предполагаемый диапазон изменения 30–720, что соответствует 0.5 - 12 часов.

4) Пока буферы не заполнены (len != W + 1) — сигнал не считается.

5) Когда буферы заполнены, для каждого нового интервала:
Моментум цены:
tr = price_series[-1] / price_series[0] - 1
где price_series[0] — самое старое значение, price_series[-1] — текущее. В окне ровно W+1 точек, т.е. tr — это доходность за W интервалов.

Волатильность цены (std возвратов по окну W):
rets[i] = price_series[i] / price_series[i-1] - 1  для i от 1 до W
meanRet = mean(rets)
sigPx = sqrt( sum((rets[i] - meanRet)^2) / (W - 1) ) * sqrt(W)
⚠️ Важно: в C++ цикл идёт for i in [size-W, size), где size = W+1, т.е. индексы от 1 до W включительно — ровно W значений rets. Деление на W-1 — выборочное СКО.

Статистика потока по окну W:
flow_window = flow_series[-W:]      # последние W значений (не W+1!)
meanFlow = mean(flow_window)
stdFlow  = sqrt( sum((flow[i] - meanFlow)^2) / (W - 1) )

Нормировки:
pz   = tr / sigPx
intz = meanFlow * sqrt(W) / stdFlow
comb = pz - intz
Защита: если sigPx < 1e-9 или stdFlow < 1e-9 → comb = 0, сигнал = нейтральный.

6) Сигнал:
if comb >=  sigma: signal = +1   (Buy)
elif comb <= -sigma: signal = -1 (Sell)
else: signal = 0

3. Подбор гиперпараметров
Параметры для перебора (сетка, задаётся в конфиге):
- interval_sec: [10, 20, 30, 60, 120, 180, 300]
- window_size W: [30, 60, 120, 180, 360, 720]
- sigma: [1.0, 1.5, 2.0, 2.5, 3.0, 3.5]
- price_source: [vwap, close]
- take_profit: [0.005, 0.0075, 0.01] (0.5–1.0%)
- stop_loss: [0.0025, 0.005, 0.01]
- max_hold_sec: [1800, 3600, 7200, 14400]

Логика бэктеста (упрощённая, event-driven):
- Одна позиция одновременно. Пока позиция открыта — новые сигналы игнорируются.
- Вход: по сигналу, по цене close секунды, в которую зафиксирован сигнал.
- Выход по первому из:
а) Take-profit: (exit_price / entry_price - 1) >= TP для long (и симметрично для short)
б) Stop-loss: (exit_price / entry_price - 1) <= -SL для long
в) Timeout: прошло max_hold_sec
- Проверка TP/SL — по high / low каждой секунды удержания (intrabar). Если в одной секунде задеты и TP, и SL — считать SL сработавшим первым (консервативно). Параметризовать conservative_intrabar=True.
- Издержки: fee_bps (комиссия taker + slippage) применяется к обеим сторонам сделки. Параметр, по умолчанию 0.16% от объема позиции.
- Funding не учитываем.

Метрики на fold:
- Net PnL в % (сумма по сделкам с учётом издержек)
- Число сделок
- Win rate
- Profit factor
- Sharpe по сделкам: mean(returns) / std(returns) * sqrt(N_trades) (или годовой — на твой выбор, укажи явно)
- Max drawdown по equity curve (по закрытым сделкам)
- Средняя длительность удержания
- Число сигналов Buy / Sell
- Доля времени в позиции

4.  Walk-forward / train-test разбиение
- Данные — один файл .csv. Разделить на N фолдов (параметр n_folds, по умолчанию 5).
- Для каждого фолда: train = предыдущие K дней, test = следующие M дней. Схема — expanding или rolling, параметр walk_forward_mode ∈ {expanding, rolling}.
- Оптимизация параметров — только на train. Метрики отчёта — только на test.
- Критерий выбора лучших параметров на train — задаётся параметром objective ∈ {sharpe, profit_factor, net_pnl, calmar}. По умолчанию sharpe.
- Итоговый отчёт: таблица по фолдам (train-метрики лучших параметров + test-метрики), агрегат по test (median, mean, std, % прибыльных фолдов), и таблица «топ-10 конфигураций по median(test_sharpe)».
